│  **4. Root cause explanation:**                                                                                                                                                                                                                                                                                                                        │
│  Both functions look up a string pointer from a statically‑initialized array using a calculated index (`cmd_id - CMD_POLL` or `reply_id - REPLY_ACK`). The arrays are sparsely populated with designated initializers; any entry that is not explicitly initialized is set to `NULL`. The code does **not** verify that the retrieved pointer is       │
│  non‑NULL before dereferencing it (`name[0]`). When an unsupported or future command/reply identifier is supplied that maps to an uninitialized slot, `name` becomes `NULL` and the subsequent dereference triggers undefined behaviour (typically a crash).                                                                                           │
│                                                                                                                                                                                                                                                                                                                                                        │
│  **5. Relevant input‑to‑sink (or input‑to‑dangerous‑operation) flow:**                                                                                                                                                                                                                                                                                 │
│  1. Caller supplies `cmd_id` (or `reply_id`) to `osdp_cmd_name` / `osdp_reply_name`.                                                                                                                                                                                                                                                                   │
│  2. The function checks only the numeric range, not whether the specific identifier has a defined name entry.                                                                                                                                                                                                                                          │
│  3. The identifier is used as an index into the `names` lookup array.                                                                                                                                                                                                                                                                                  │
│  4. If the corresponding array entry is `NULL`, the function proceeds to read `name[0]`.                                                                                                                                                                                                                                                               │
│  5. Dereferencing `NULL` leads to a runtime fault (crash).                                                                                                                                                                                                                                                                                             │
│                                                                                                                                                                                                                                                                                                                                                        │
│  **6. Security impact:**                                                                                                                                                                                                                                                                                                                               │
│  An attacker who can influence the command or reply identifier (e.g., via a crafted OSDP message) can cause the library to dereference a `NULL` pointer, resulting in a process abort. This constitutes a denial‑of‑service vulnerability. While it does not directly enable code execution, it can be leveraged to disrupt service and may be         │
│  combined with other bugs for further impact.                                                                                                                                                                                                                                                                                                          │
│                                                                                                                                                                                                                                                                                                                                                        │
│  **7. Severity:** MEDIUM (Denial‑of‑service due to predictable crash; no direct code execution)                                                                                                                                                                                                                                                        │

│  **2. Unsafe behavior removed**                                                                                                                                                                                                                                                                                                                        │
│  Dereferencing a potentially `NULL` pointer (`name[0]`) when the lookup array entry is uninitialized, which could cause a null‑pointer dereference (CWE‑476) and crash the process.                                                                                                                                                                    │
│                                                                                                                                                                                                                                                                                                                                                        │
│  **3. Security control or validation added**                                                                                                                                                                                                                                                                                                           │
│  *Added an explicit `NULL` check* for the retrieved `name` pointer before any dereference. If `name` is `NULL`, the function now returns `"UNKNOWN"`.                                                                                                                                                                                                  │
│                                                                                                                                                                                                                                                                                                                                                        │
│  **4. Why the patch removes the root cause**                                                                                                                                                                                                                                                                                                           │
│  The root cause is the assumption that every index within the validated numeric range maps to a non‑`NULL` string literal. Sparse table initialization leaves many entries as `NULL`. By verifying `name != NULL` prior to accessing `name[0]`, the functions no longer perform an illegal dereference when an unsupported or future command/reply     │
│  identifier is supplied, thereby eliminating the null‑pointer dereference vulnerability while preserving the original behavior for valid identifiers.                                                                                                                                                                                                  │
